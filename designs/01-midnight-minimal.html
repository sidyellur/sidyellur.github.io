tethertether-memory

A shared memory layer for personal agents — context that follows you instead of dying with the session.

tether is an MCP server backed by a single local SQLite file. Any MCP-compatible agent can remember, recall, link and forget durable notes — facts about you, your projects, your preferences. It runs local-only with zero configuration. Point it at a hosted libSQL/Turso primary and that same file becomes an embedded replica, syncing memory across every device in near-real-time.

Recall is hybrid: keyword results from FTS5 are fused with semantic vector results, so “automobile” finds the note about your car. The embedding model is small, static, and runs locally — no network, no API key. From the seed hits, tether walks an associative usage graph built from three deterministic local sources: semantic nearest-neighbours, explicit link() calls, and hebbian edges, where memories recalled together get wired together over time. Every hit carries a via receipt explaining why it surfaced.

Recall is seed-dominant by design — top direct matches are locked in place and associations only fill the slots below them, so turning association on can never demote a good hit. The store also self-organizes: a hub-curated boot index surfaces load-bearing memories, the ones with the highest behavioral degree, alongside recent ones, and an opt-in sweep soft-archives memories that are both old and behaviorally isolated. Nothing is ever hard-deleted. Optional crystallization detects dense clusters of related memories and offers them up to be named as principles — tether finds the structure, the agent supplies the words.

Every feature degrades cleanly back to plain keyword recall. It is deliberately a convenience layer: more useful when present, never a thing that breaks the agent when it is not.

Returning query-centered excerpts instead of full bodies cut a single recall response from 66.9 KB to 2.0 KB.

02 PyPI

cleat

A headless terminal layer for AI agents — structured results instead of escape-code soup.

cleat runs a persistent shell session behind a PTY, parses its byte stream for OSC 133 shell-integration marks, and exposes it to an agent over MCP as structured results: stdout, a real exit_code, the files touched.

The core insight is that when you scrape a PTY, the exit code is not in the stream at all. The shell knows $? and never prints it. So cleat injects OSC 133 marks into the shells it spawns and parses them back out. Because the session persists, cd, export, activated venvs and ssh sessions all carry across calls — something a fresh subprocess per command simply cannot do.

Every response carries a state derived from termios flags and the foreground process group: facts only the process holding the PTY can read, not guessed from output timing. The states are idle, running, awaiting-input, password and tui — and cleat refuses to type into a password prompt without explicit human consent.

Marks are nonce-authenticated. A command could otherwise print a fake OSC 133 sequence to its own stdout to forge a clean exit code, so each session gets a fresh secrets.token_hex(8) nonce embedded in every mark cleat injects. A mark with a missing or wrong k= is ignored outright and surfaced as spoofed_marks, so the agent can tell when a program lied about how it finished. None of this is a terminal emulator, and none of it modifies yours — cleat is terminal-agnostic.

03 v1 · v2 Solo

Black Diamond Brawl

A Road Rash-style downhill snowboarding combat racer, built solo as a learning project.

Each run is a single race down a fixed-length, seeded, procedurally generated slope ending at a finish line. You dodge trees, rocks and moguls, catch trick air off moguls and hill crests — crests launch you automatically at speed — and shove or ski-pole your way past AI rivals racing the same course. Score comes from finishing fast, landing hits on rivals, near-misses and tricks. Wipe out hard before the line and the run ends early.

The renderer is a classic segment-based pseudo-3D: the behind-the-rider, road-rushing-at-you look of OutRun and Road Rash, drawn with pixel art sprites. All art and atmosphere is generated in code at boot — there are no image files in the repository at all. Colour is governed by a palette module and enforced by a build gate that fails if any gameplay-relevant edge drops below ΔL* 12, or any sprite outline below ΔL* 25 against the snow behind it.

It also ships with a headless seeded combat simulation and a solvability model, so balance is verified without ever opening a browser. v1 shipped across nine phases; the v2 visual overhaul is complete.

About

I am an engineer who builds developer tooling for AI agents. The through-line in my work is giving agents honest primitives: memory that persists and can explain why it surfaced something, and a terminal that reports what actually happened rather than what the output happened to look like.

I care about software that degrades gracefully — features that make a tool better when they are available and never break it when they are not. Most of what I build runs entirely on your machine, with no keys and no network. Lately that instinct has spilled over into a video game that refuses to ship a single image file.
