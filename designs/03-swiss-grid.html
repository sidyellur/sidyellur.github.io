01

tether

A shared memory layer for personal agents.

An MCP server backed by a single local SQLite file. Any MCP‑compatible agent can remember, recall, link and forget durable notes — facts about you, your projects, your preferences — so context follows you between sessions instead of dying with each one.

Tech
Python  ·  MCP  ·  SQLite / FTS5  ·  libSQL / Turso  ·  local static embeddings
Status
v0.5.1  ·  PyPI: tether‑memory
Source
github.com/sidyellur/tether
$ claude mcp add tether -- uvx tether-memory
  1. .01 Local by default

    Runs local‑only with zero configuration. Point it at a hosted libSQL/Turso primary and the same file becomes an embedded replica, syncing memory across every device in near‑real‑time.

  2. .02 Hybrid recall

    Keyword results from FTS5 are fused with semantic vector results, so “automobile” finds the note about your “car”. The embedding model is small, static and runs locally — no network, no API key.

  3. .03 Associative graph

    Recall follows an associative usage graph to related memories. Edges come from three deterministic local sources: semantic nearest‑neighbours, explicit link() calls, and hebbian edges — memories recalled together get wired together over time. Every hit carries a via receipt explaining why it surfaced.

  4. .04 Seed‑dominant

    Top direct matches are locked in place and associations only fill the slots below them, so turning association on never demotes a good hit.

  5. .05 Self‑organizing

    A hub‑curated boot index surfaces load‑bearing memories — the ones with the highest behavioral degree — alongside recent ones. An opt‑in sweep soft‑archives memories that are both old and behaviorally isolated. Nothing is ever hard‑deleted.

  6. .06 Crystallization

    Optional: it detects dense clusters of related memories and offers them up to be named as principles. tether finds the structure; the agent supplies the words.

  7. .07 Degrades cleanly

    Every feature falls back to plain keyword recall. It is deliberately a convenience layer — more useful when present, never breaking the agent when degraded.

Measured
2.0KB

Recall response size, down from 66.9KB, by returning query‑centered excerpts instead of full bodies.

02

cleat

A headless terminal layer for AI agents.

Runs a persistent shell session behind a PTY, parses its byte stream for OSC 133 shell‑integration marks, and exposes it to an agent over MCP as structured results — stdout, a real exit_code, files touched — instead of raw escape‑code soup.

Tech
Python  ·  MCP  ·  PTY / termios  ·  OSC 133  ·  pyte
Status
PyPI: cleat
Source
github.com/sidyellur/cleat
$ claude mcp add cleat -- uvx cleat
  1. .01 The exit code problem

    The core insight: when you scrape a PTY, the exit code isn’t in the stream at all. The shell knows $? but never prints it. cleat injects OSC 133 marks into the shells it spawns and parses them back out.

  2. .02 Persistent session

    cd, export, activated venvs and ssh sessions all carry across calls — something a fresh subprocess per command cannot do.

  3. .03 Real state

    Every response carries a state derived from termios flags and the foreground process group — facts only the process holding the PTY can read, never guessed from output timing. States: idle, running, awaiting‑input, password, tui.

  4. .04 Consent at the prompt

    It refuses to type into a password prompt without explicit human consent.

  5. .05 Nonce‑authed marks

    A command can print a fake OSC 133 sequence to its own stdout to forge a clean exit code. Each session gets a fresh secrets.token_hex(8) nonce embedded in every mark cleat injects; a mark with a missing or wrong k= is ignored outright and surfaced as spoofed_marks, so the agent can tell when a program lied about how it finished.

  6. .06 Terminal‑agnostic

    Not a terminal emulator, and not a modification to yours.

Structured result
{ "stdout": "…", "exit_code": 0, "completed": true, "state": "idle" }

What the agent receives, in place of escape‑code soup.

03

Black Diamond Brawl

A downhill snowboarding combat racer.

A Road Rash‑style downhill snowboarding combat racer, built solo as a learning project. Each run is a single race down a fixed‑length, seeded, procedurally generated slope, ending at a finish line.

Tech
Phaser 3  ·  TypeScript  ·  Vite  ·  segment‑based pseudo‑3D renderer
Status
v1 complete, 9 phases  ·  v2 visual overhaul complete
Source
github.com/sidyellur/black‑diamond‑brawl
  1. .01 The run

    Dodge trees, rocks and moguls. Catch trick air off moguls and hill crests — crests launch you automatically at speed. Shove or ski‑pole your way past AI rivals racing the same course.

  2. .02 Scoring

    Score comes from finishing fast, landing hits on rivals, near‑misses, and tricks. Wipe out hard before the line and the run ends early.

  3. .03 Pseudo‑3D renderer

    A classic segment‑based pseudo‑3D renderer gives the behind‑the‑rider, road‑rushing‑at‑you look — the OutRun and Road Rash lineage — with pixel art sprites.

  4. .04 Art without assets

    All art and atmosphere is generated in code at boot; there are no image files in the repository at all. Colour is governed by a palette module and enforced by a build gate that fails if any gameplay‑relevant edge drops below ΔL* 12, or any sprite outline below ΔL* 25 against the snow behind it.

  5. .05 Verified headless

    Ships with a headless seeded combat simulation and a solvability model, so balance is verified without a browser.

Asset count
0

Image files in the repository. Every sprite, gradient and weather effect is drawn in code at boot.
