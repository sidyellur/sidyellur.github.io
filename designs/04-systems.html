tether

v0.5.1

A shared memory layer for personal agents. An MCP server backed by one local SQLite file: any compatible agent can remember, recall, link and forget durable notes — facts about you, your projects, your preferences — so context follows you between sessions instead of dying with each one.

  • Hybrid recall. FTS5 keyword hits fused with semantic vector results, so “automobile” finds the note about your car. The embedding model is small, static and local — no network, no API key.
  • An associative usage graph. Edges come from three local deterministic sources: semantic nearest-neighbours, explicit link() calls, and hebbian edges — memories recalled together get wired together over time. Every hit carries a via receipt explaining why it surfaced.
  • Seed-dominant ranking. Top direct matches are locked in place and associations only fill the slots below them, so turning association on never demotes a good hit.
  • Local first, synced if you want it. Zero configuration on its own; point it at a hosted libSQL/Turso primary and the same file becomes an embedded replica syncing memory across every device in near-real-time.
  • The store self-organises. A hub-curated boot index surfaces load-bearing memories by behavioural degree alongside recent ones, and an opt-in sweep soft-archives what is both old and behaviourally isolated. Nothing is ever hard-deleted.
  • Optional crystallisation. It detects dense clusters of related memories and offers them up to be named as principles — tether finds the structure, the agent supplies the words.
  • Everything degrades cleanly to plain keyword recall. It is deliberately a convenience layer: more useful when present, never broken when reduced.

cleat

on PyPI

A headless terminal layer for AI agents. It runs a persistent shell session behind a PTY, parses the byte stream for OSC 133 shell-integration marks, and exposes it over MCP as structured results — stdout, a real exit code, files touched — instead of raw escape-code soup.

  • The core insight: the exit code is not in the stream at all. The shell knows $? but never prints it. cleat injects OSC 133 marks into the shells it spawns and parses them back out.
  • The session persists. cd, export, activated venvs and ssh sessions all carry across calls — something a fresh subprocess per command cannot do.
  • Real state, not inferred state. Every response carries a state derived from termios flags and the foreground process group: idle, running, awaiting-input, password, tui. Facts only the process holding the PTY can read, never guessed from output timing.
  • Nonce-authenticated marks. A command can print a fake OSC 133 sequence to its own stdout to forge a clean exit code. Each session gets a fresh secrets.token_hex(8) nonce embedded in every mark cleat injects; a mark with a missing or wrong k= is ignored outright and surfaced as spoofed_marks, so the agent can tell when a program lied about how it finished.
  • Consent at the password prompt. It refuses to type into one without an explicit human go-ahead.
  • Terminal-agnostic. Not a terminal emulator, and not a modification to yours.

Black Diamond Brawl

v1 complete

A downhill snowboarding combat racer in the Road Rash mould, built solo as a learning project. Each run is a single race down a fixed-length, seeded, procedurally generated slope, ending at a finish line.

  • Race and brawl at the same time. Dodge trees, rocks and moguls; catch trick air off moguls and hill crests, which launch you automatically at speed; shove or ski-pole your way past AI rivals racing the same course.
  • Scoring rewards commitment. Points come from finishing fast, landing hits on rivals, near-misses and tricks — but wipe out hard before the line and the run ends early.
  • Classic segment-based pseudo-3D renderer. The behind-the-rider “road rushing at you” look of OutRun and Road Rash, with pixel art sprites.
  • There are no image files in the repository at all. Every bit of art and atmosphere is generated in code at boot. Colour is governed by a palette module and enforced by a build gate that fails if any gameplay-relevant edge drops below ΔL* 12, or any sprite outline below ΔL* 25 against the snow behind it.
  • Balance verified without a browser. It ships with a headless seeded combat simulation and a solvability model.
  • Shipped in phases. v1 complete across nine of them, plus a completed v2 visual overhaul.

About

Engineer, mostly at the layer below

Most of what I build sits underneath something else: a memory store an agent talks to, a shell an agent drives, a renderer a game draws through. That layer is where the interesting failure modes live — a forged exit code, a recall that quietly demotes the right answer, a sprite that vanishes against the snow behind it.

So the through-line is honesty about state. Read facts from the process rather than inferring them from output. Attach a receipt to every result. Degrade to something plain and correct when the clever path is unavailable, and never break the caller on the way down.

The game is the same instinct pointed somewhere less serious: generate everything in code, then let a build gate — not my eyes — decide whether you can actually see it.
