Memory — Python · MCP · SQLite

tetherA shared memory layer for personal agents.

One MCP server, one local SQLite file, and four verbs — remember, recall, link, forget — so that what an agent learns about you survives the session it learned it in.

Status
v0.5.1
Stack

  • MCP
  • SQLite / FTS5
  • libSQL / Turso
  • Static embeddings
Install
claude mcp add tether \
  -- uvx tether-memory
Package
tether-memory on PyPI
Repository
github.com/sidyellur/tether

Agents are amnesiacs by construction. Every session opens on a blank desk; whatever was established last time — how your repositories are laid out, which database you actually use, that you prefer the terse answer — has to be established again. tether is the durable notebook that sits beside the agent instead of inside it: an MCP server backed by a single SQLite file on your own disk, which any MCP-compatible client can write to and read from.

It runs local-only with zero configuration, which is the point — nothing to sign up for, nothing to keep alive. Point it at a hosted libSQL/Turso primary and that same file quietly becomes an embedded replica, syncing memory across every device you work from in near-real-time. The storage model does not change; only its reach does.

Retrieval is hybrid. A recall fuses keyword results from SQLite’s FTS5 index with semantic vector results, so a query for “automobile” still finds the note you wrote about your car. The embedding model is deliberately small and static and runs on your machine: no network call, no API key, no third party learning what you asked.

Above that sits an associative usage graph. Edges come from three local, deterministic sources — semantic nearest-neighbours, explicit link() calls, and hebbian edges, where memories recalled together get wired together over time. Nothing is inferred by a model in the cloud. And because association is the kind of thing that goes wrong invisibly, every hit carries a via receipt explaining exactly why it surfaced.

Memories recalled together get wired together. Every hit carries a receipt explaining why it surfaced.

Recall is seed-dominant. Top direct matches are locked in place and associations are only ever allowed to fill the slots below them, so switching association on can never demote a good hit — a small rule that makes the clever feature safe to leave enabled.

The store also tidies itself. A hub-curated boot index surfaces the load-bearing memories — those with the highest behavioral degree — alongside the most recent ones, so a fresh session opens on what matters rather than on what happened last. An opt-in sweep soft-archives memories that are both old and behaviorally isolated. Nothing is ever hard-deleted.

There is an optional final move: crystallization. tether watches for dense clusters of related memories and offers them up to be named as principles. It finds the structure; the agent supplies the words.

Returning query-centred excerpts instead of full bodies cut a recall response from 66.9 KB to 2.0 KB.

Response payload, before & after

Every one of those features degrades cleanly to plain keyword recall. That is the governing constraint: tether is a convenience layer, more useful when it is present, and never the reason an agent breaks when it is not.

Terminals — Python · MCP · PTY

cleatA headless terminal layer for AI agents.

A persistent shell running behind a PTY, its byte stream parsed for OSC 133 shell-integration marks and handed to an agent as structured results — not as escape-code soup.

Stack

  • MCP
  • PTY / termios

  • pyte
Install

  -- uvx cleat
Package
cleat on PyPI
Session states
idle, running, awaiting-input, password, tui
Repository
github.com/sidyellur/cleat

Give an agent a terminal and you immediately hit a problem that looks trivial and is not. You can scrape a pseudo-terminal for everything the shell prints — but the one fact you most need is not printed anywhere. The shell knows $?; it simply never says it out loud.

When you scrape a PTY, the exit code isn’t in the stream at all.

The premise

cleat’s answer is to stop guessing. It injects OSC 133 shell-integration marks into the shells it spawns and parses them back out of the stream, turning a wall of escape codes into an honest record: what was printed, what the command actually returned, which files it touched. 

{ "stdout": "...", "exit_code": 0,
  "completed": true, "state": "idle" }

The session persists between calls, which is the other half of the idea. A cd holds. An export holds. An activated virtualenv, an ssh session — all of it carries forward, because it is one long-lived shell rather than a fresh subprocess per command. No amount of cleverness gets a subprocess to remember where it was.

Every response also carries a state, and that state is read rather than inferred. It is derived from termios flags and the foreground process group — facts available only to the process holding the PTY, never guessed from output timing. The shell is either idle, running, awaiting-input, at a password prompt, or inside a tui. When it is a password prompt, cleat refuses to type into it without explicit human consent.

Then there is the case of a program that lies. A command can print a counterfeit OSC 133 sequence to its own stdout and hand the agent a clean exit code it never earned. So every session gets a fresh secrets.token_hex(8) nonce embedded in every mark cleat injects; a mark arriving with a missing or wrong k= is ignored outright and surfaced as spoofed_marks. The agent gets told when something misrepresented how it finished.

None of this asks anything of your own setup. cleat is terminal-agnostic — not a terminal emulator, not a patch to the one you already use.

Games — Phaser 3 · TypeScript · Vite

Black Diamond BrawlA downhill snowboarding combat racer.

Road Rash on a snowboard: one seeded, procedurally generated slope, a finish line, and a handful of rivals who would rather you did not reach it. Built solo, as a learning project.

Art assets

Contrast gate
Build fails below ΔL* 12 on gameplay edges, ΔL* 25 on sprite outlines.
Repository
github.com/sidyellur/black-diamond-brawl

A run is a single race: a fixed-length, seeded, procedurally generated slope with a finish line at the bottom of it. You dodge trees, rocks and moguls on the way down, catch trick air off the moguls and the hill crests — at speed, a crest launches you whether you asked for it or not — and shove or ski-pole your way past AI rivals racing the same course you are.

Score is assembled from finishing fast, landing hits on rivals, threading near-misses, and landing tricks, which means the fastest line and the highest-scoring line are rarely the same line. Wipe out badly enough before the finish and the run simply ends early.

The look is a classic segment-based pseudo-3D renderer — the behind-the-rider, road-rushing-at-you perspective of OutRun and Road Rash — with pixel art sprites laid over it. It is a technique older than the hardware most people will play it on, and it still reads instantly.

All art and atmosphere is generated in code at boot. There are no image files in the repository at all.

Doing it that way makes colour a program rather than an asset, so colour gets governed like one. A palette module owns every value, and a build gate enforces it: the build fails if any gameplay-relevant edge drops below ΔL* 12, or if any sprite outline falls below ΔL* 25 against the snow behind it. A rock you cannot see against a white slope is not a difficulty setting; it is a bug, and it is caught before it ships.

Balance is held to the same standard. The game ships with a headless seeded combat simulation and a solvability model, so a course can be proven survivable and a fight proven fair without anyone opening a browser to check.

Siddharth Yellur is an engineer who builds developer tooling for AI agents — and, lately, a video game.

The through-line in the work is a preference for the layer nobody demos: memory that persists after the window closes, a terminal that can prove what a command returned, a renderer whose colours are checked by the build rather than by eye. Small tools, made to be honest about what they know, and to fail quietly rather than loudly when they do not know it.

Most of it is Python and TypeScript, most of it is open source, and most of it started because the thing did not exist and the absence got annoying enough.
