Engineer · Developer tooling

I build developer tooling for AI agents — and, lately, a video game.

Most of what I make sits underneath something else. A memory layer an agent can write to and read back from months later. A terminal an agent can actually trust the output of. Small, local, quiet things that do one job carefully and then get out of the way.

The newest one is a snowboarding game, which turned out to be an entirely different sort of problem — and the reason I now know rather more about pseudo-3D renderers than I ever planned to.

Three projects below, with the details left in. Everything is open source, and the two tools install in a single line.

01

tether

a shared memory layer for personal agents

tether is an MCP server backed by a single SQLite file on your own machine. Any MCP-compatible agent can remember, recall, link and forget durable notes — facts about you, your projects, your preferences — so context follows you between sessions instead of dying with each one.

It runs local-only with zero configuration. Point it at a hosted libSQL/Turso primary and that same file quietly becomes an embedded replica, syncing memory across every device in near-real-time. Nothing about the shape of the thing changes; the file just learns to talk to its siblings.

recall is hybrid. Keyword results from FTS5 are fused with semantic vector results, so asking about “automobile” still finds the note where you happened to write “car”. The embedding model is small, static and runs locally — no network call, no API key, nothing to sign up for.

From a hit it walks out along an associative usage graph. The edges come from three local, deterministic sources: semantic nearest-neighbours, explicit link() calls, and hebbian edges — memories recalled together get wired together over time. Every hit carries a via receipt explaining why it surfaced, so nothing arrives unexplained.

66.9KB→2.0KB What a recall response weighs once it returns query-centred excerpts instead of full bodies.

  • Recall stays seed-dominant. The top direct matches are locked in place and associations only fill the slots beneath them, so turning association on never demotes a good hit.
  • The store tends itself. A hub-curated boot index surfaces load-bearing memories — the ones with the highest behavioural degree — alongside the recent ones, and an opt-in sweep soft-archives memories that are both old and behaviourally isolated. Nothing is ever hard-deleted.
  • Optional crystallization notices dense clusters of related memories and offers them up to be named as principles. tether finds the structure; the agent supplies the words.
  • Every feature degrades cleanly back to plain keyword recall. It is deliberately a convenience layer — more useful when it is there, never something that breaks the agent when it isn't.

02

cleat

a headless terminal layer for AI agents

cleat runs a persistent shell session behind a PTY, parses its byte stream for OSC 133 shell-integration marks, and hands an agent structured results over MCP — stdout, a real exit code, files touched — instead of raw escape-code soup.

The insight it is built on is small and faintly maddening: when you scrape a PTY, the exit code isn't in the stream at all. The shell knows $? perfectly well and simply never prints it. So cleat injects OSC 133 marks into the shells it spawns, and parses them back out on the way through.

Because the session persists, cd, export, an activated venv and an open ssh session all carry across calls — something a fresh subprocess per command can never do. 

{ "stdout": "...", "exit_code": 0,
  "completed": true, "state": "idle" }
  • Every response carries a state derived from termios flags and the foreground process group — facts only the process holding the PTY can read, never guessed from output timing. The states are idle, running, awaiting-input, password and tui.
  • It refuses to type into a password prompt without explicit human consent.
  • Nonce-authenticated marks. A command could print a fake OSC 133 sequence to its own stdout and forge itself a clean exit code. So each session gets a fresh secrets.token_hex(8) nonce embedded in every mark cleat injects; a mark with a missing or wrong k= is ignored outright and surfaced as spoofed_marks — the agent gets to know when a program lied about how it finished.
  • Terminal-agnostic. Not a terminal emulator, and not a modification to yours.

03

Black Diamond Brawl

a downhill snowboarding combat racer

A Road Rash-style downhill snowboarding combat racer, built solo as a learning project. Each run is one race down a fixed-length, seeded, procedurally generated slope, ending at a finish line.

You dodge trees, rocks and moguls; you catch trick air off moguls and hill crests — crests launch you automatically once you're carrying speed — and you shove or ski-pole your way past AI rivals racing the same course. Score comes from finishing fast, landing hits on rivals, near-misses and tricks. Wipe out hard before the line and the run simply ends early.

Underneath it is a classic segment-based pseudo-3D renderer, the old trick behind the behind-the-rider, road-rushing-at-you look from OutRun and Road Rash, drawn here with pixel art sprites.

No image files. Not one. All of the art and atmosphere is generated in code at boot — there are no image files anywhere in the repository.

  • Colour is governed by a palette module and enforced by a build gate that fails if any gameplay-relevant edge drops below ΔL* 12, or any sprite outline below ΔL* 25 against the snow behind it.
  • It ships with a headless seeded combat simulation and a solvability model, so balance gets verified without ever opening a browser.
  • v1 is complete across nine phases; the v2 visual overhaul is done too.
